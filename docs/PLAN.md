# Implementation and acceptance plan

1. **Feasibility:** inspect supplied sources and hardware; verify E: writes; source probes; screened real metadata and OA JATS parsing; measured pilot; first TF-IDF/BM25 retrieval; architecture, screening and evaluation protocol. Acceptance requires actual passages, not fixtures.
2. **Baseline:** resumable paging, versioned raw data, identifier deduplication, section/table parsing, positional postings, flat TF-IDF and BM25, API, persistent sessions, source browser; reproducible baseline runs.
3. **Evidence:** visible food normalization, structure-aware scores, CPU dense/hybrid retrieval, bounded reranking; separately validated stance/context processing and targeted counterevidence; inspectable traces and source spans.
4. **Workflows:** public investigation, professional comparisons, research diagnostics, source navigation/highlighting, notes, exports and contextual follow-ups; desktop/mobile/keyboard browser checks.
5. **Scale:** extend discovery by topic and date, refresh metadata/status, monitor actual storage/RAM and topic/full-text selection effects. No final paper cap. Stop based on measured budget, coverage or compute and preserve checkpoints.
6. **Delivery:** freeze experiments, collect independent judgments, execute baselines/ablations, document failures, finish course report and demo materials. User provides actual authorship and recording; do not fabricate either.

Track each requirement in STATUS.md. A milestone is complete only after its stated acceptance checks pass. Implementation continues from durable code/manifests, not from recollection of chats.
